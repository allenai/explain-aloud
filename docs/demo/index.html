why does this plugin exist?
✳

Working with coding agents has inverted the job: you write less code and read more of it — plans, diffs, explanations, trade-offs — and every answer arrives as a wall of dense text that you are expected to parse in full, every single time, which is exhausting in a way that compounds over a day of brainstorming, deciding, and instructing rather than typing.

Screen readers and read-aloud tools don't really help, because they recite the text verbatim, and text that was built for reading — markdown tables, file paths, CLI flags, bullet hierarchies — sounds terrible when spoken; what you actually want is what a good teacher does with a slide: not read it to you, but explain it, leading with the conclusion, unpacking the jargon, and pointing at the table instead of reciting its rows.

That's what explain-aloud does: after a reply, a small model rewrites it into a spoken explanation that is self-sufficient enough to act on without reading, and plays it through a local neural voice, with pause, rewind, and a live progress readout.
